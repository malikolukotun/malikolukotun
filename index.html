Deriving backpropagation by hand, then coding it

Most introductions to backpropagation gesture at the chain rule and then hand you loss.backward(). This note does the opposite: we compute the gradient of a tiny two-layer network symbolically, watch every partial derivative land where it should, and only then write a ~100-line autograd engine that reproduces them numerically.

The key realization is that backpropagation is not an algorithm for "training networks" — it is an algorithm for reusing intermediate results of the chain rule. Once you see the computational graph as the object the math is happening on, the engine writes itself: each node stores how to compute its local derivative, and a single reverse topological pass accumulates them. Linear algebra is the grammar of neural networks

A matrix multiplication is usually taught as a formula to memorize. It is better understood as the grammar of a sentence: W x says "measure x along the directions that matter to W." This note collects the four or five interpretations of a matrix that keep recurring across machine learning.

We walk through: (1) a matrix as a list of dot-product probes, (2) as a change of basis, (3) as a geometric transformation (rotate, stretch, shear), and (4) as a low-rank compression of a huge table of associations. The punchline for neural networks: training is nothing but nudging the grammar so that the sentences it produces score better. Full version on Substack →

What Turing actually proved (and what he didn't)

The halting problem is often summarized as "computers can't solve everything." True, but the shape of the proof matters more than the slogan: Turing showed that a single self-referential construction — feed a machine its own description — collapses any would-be decider. The same diagonal trick shows up in Gödel, Cantor, and Rice's theorem.

This note traces the diagonal argument across all four results and argues they are one idea wearing different clothes. The payoff is practical: recognizing the pattern tells you immediately which questions about programs are hopeless in general, and where the escape hatches (decidable fragments, approximation, verification of restricted systems) actually live.
